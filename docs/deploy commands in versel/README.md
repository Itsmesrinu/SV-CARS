# Deploying to Vercel — Windows runbook

Move this project to another Windows laptop as a zip, push it to GitHub, deploy it to
Vercel, and know exactly where the secrets live.

Every command below was run and verified on this machine on **2026-09-07**
(Node v24.16.0, npm 12.0.1, Windows 11). Where a command is *not* the obvious one,
there is a reason stated — the obvious one was tested and it broke something.

> **Shell:** all PowerShell unless a block says `Git Bash`. Do not paste PowerShell
> into Git Bash or the other way round; `robocopy`, `tar.exe` and path quoting all
> behave differently.

### 0.2 Known type error — read before you panic on the other laptop

```
tests/ui/fixtures.ts(74,14): error TS2741: Property 'heroImage' is missing in type
'{ whatsappPhone: ...; }' but required in type 'SettingsDTO'.
```

A Playwright fixture wasn't updated when `heroImage` was added to `SettingsDTO`.

**It does not block deployment.** `npm run build` runs `vite build`, which does not

`npm run ui:review` may misbehave until the fixture gets its `heroImage` field.

Fix it now if you want a clean tree; it is a one-line addition to the fixture.

### 0.3 Commit everything

The zip carries `.git`, so anything uncommitted travels as a *working-tree change*,
not as history. Commit first so the other laptop starts clean.

```powershell
cd "C:\Users\sreenivasulu.c04\Downloads\OLD-Downloads-BACKUP\test-sv-cars-2"

# Confirm the secret files are ignored BEFORE staging anything.
# Each must echo the filename back. Silence means it is NOT ignored — stop and fix .gitignore.

git check-ignore -v node_modules
git check-ignore -v .ui-review
git check-ignore -v dist

git add -A
git status --short          # eyeball this list; .env must NOT appear

```

> the history and in anyone's clone.

## Part 1 — Zip it (this laptop)

Two steps: stage a filtered copy with `robocopy`, then zip the staged copy with
`tar.exe`.

### 1.1 Stage a filtered copy

```powershell
$src   = "C:\Users\sreenivasulu.c04\Downloads\OLD-Downloads-BACKUP\test-sv-cars-2"
$stage = "$env:TEMP\sv-cars-transfer"

Remove-Item -Recurse -Force $stage -ErrorAction SilentlyContinue

robocopy $src $stage /E `
  /XD node_modules "ALL UI SKILLS" .ui-review dist .vercel playwright-report test-results ".claude\skills" `
  /XF .env *.log `
  /NFL /NDL /NJH /NJS /NP

Write-Host "robocopy exit code: $LASTEXITCODE   (0 or 1 = success)"
```

`robocopy` exit codes are not standard: **0 = nothing to copy, 1 = files copied
successfully.** Anything **8 or above is a real failure.** Do not treat `1` as an error.

What each exclusion is and why:

| Excluded | Size | Why |
|---|---|---|
| `node_modules` | 284 MB | Rebuilt by `npm ci` from `package-lock.json` |
| `.ui-review` | 191 MB | Playwright screenshots; gitignored evidence, regenerated by `npm run ui:review` |
| `ALL UI SKILLS` | 136 MB | Vendored UI skills — **agent context only, zero runtime effect** |
| `dist` | 16 MB | Build output; Vercel builds its own |
| `.claude\skills` | tiny | Pointer files into `ALL UI SKILLS`; useless without it |
| `.vercel` | tiny | Machine-local project link; the new laptop makes its own |
| `.env` | 775 B | **Secrets. Never travels in a zip.** See [Part 5](#part-5) |

Everything else travels, including **`.git`** (15 MB) — so full history, all 5 commits
and the `master` branch land on the other laptop and you only need to add a remote.
`public/` (15 MB, the 43 original `.webp` files) also travels; it is your only local
backup of the car photos if Cloudinary is ever lost.

**Verify the staging before zipping:**

```powershell
Write-Host ("staged MB: " + [math]::Round((Get-ChildItem $stage -Recurse -Force | Measure-Object Length -Sum).Sum/1MB,1))
Write-Host (".git kept   : " + (Test-Path "$stage\.git"))
Write-Host (".env absent : " + (-not (Test-Path "$stage\.env")))
```

Expected: `staged MB: 29.9`, `.git kept : True`, `.env absent : True`.

### 1.2 Zip the staged copy — use `tar.exe`, not `Compress-Archive`

```powershell
$zip = "$env:USERPROFILE\Desktop\sv-cars-$(Get-Date -Format yyyyMMdd).zip"
Remove-Item $zip -Force -ErrorAction SilentlyContinue

Push-Location $stage
& "$env:SystemRoot\System32\tar.exe" -a -c -f $zip *
Pop-Location

Write-Host ("zip: $zip  " + [math]::Round((Get-Item $zip).Length/1MB,1) + " MB")
```

`tar.exe` ships with Windows 10 1803+ and Windows 11. `-a` picks the format from the
`.zip` extension, `-c` create, `-f` output file. Running it from inside `$stage` gives
you a zip with no wrapper folder.

> ### ⚠️ Do not use `Compress-Archive -Path "$stage\*"`
>
> It **silently destroys your git history.** Measured on this exact folder:
>
> | Command | Total entries | `.git` entries |
> |---|---|---|
> | `Compress-Archive -Path "$stage\*"` | 397 | **0** ❌ |
> | `Compress-Archive -Path $stage` | 399 | 168 ⚠️ partial |
> | `tar.exe -a -c -f $zip *` | **560** | **283** ✅ |
>
> `Compress-Archive` skips items carrying the Hidden attribute, and git sets Hidden on
> `.git`. The wildcard form drops the folder entirely. It exits 0 and prints no
> warning — you would only discover it on the other laptop when `git log` says
> "not a git repository".

**Verify the zip actually contains git before you delete anything:**

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$a = [System.IO.Compression.ZipFile]::OpenRead($zip)
Write-Host ("entries: " + $a.Entries.Count)
Write-Host ("git objects: " + ($a.Entries | Where-Object { $_.FullName -like '*.git/*' }).Count)
$a.Dispose()
```

Expect roughly **560 entries and ~283 git objects**. If git objects is 0, you used the
wrong command.

### 1.3 Clean up

```powershell
Remove-Item -Recurse -Force $stage
```

Then copy the zip to the other laptop (USB, OneDrive, network share). It contains no
credentials, so the transfer medium does not need to be secret.

## Part 3 — Push to GitHub

There is currently **no remote**, so this is a first push.

### 3.1 Create the repository

**Make it private.** It contains the client's business data, the admin panel structure
and the schema. Nothing here needs to be public.

**Option A — GitHub CLI (fastest):**

```powershell
gh auth login                                  # browser flow, once per machine
gh repo create sv-venkateshwara-cars --private --source=. --remote=origin
```

`--source=.` wires `origin` to the existing local repo — no clone, no re-init.

**Option B — website:**

Create an **empty** private repo at <https://github.com/new> (no README, no
`.gitignore`, no licence — those would conflict with your history), then:

```powershell
git remote add origin https://github.com/<your-username>/sv-venkateshwara-cars.git
```

### 3.2 Push

```powershell
git remote -v                     # confirm origin is set
git add -A
git status --short                # .env must NOT be listed
git commit -m "chore: prepare for Vercel deployment"

git push -u origin master
```

Your branch is `master`, not `main`. That is fine — Vercel deploys whatever GitHub
reports as the default branch. To rename it to `main` (optional, conventional):

```powershell
git branch -M main
git push -u origin main
```

Then on GitHub: **Settings → General → Default branch** → set to `main`.

### 3.3 Confirm no secret was pushed

```powershell
git log --all --full-history --name-only -- .env .env.local
```

**This must print nothing.** If it lists a commit, the secret is in your history —
rotate all four credentials immediately (new Neon password, new Cloudinary API secret,
new `JWT_SECRET`) rather than trying to scrub the history.

<a name="part-4"></a>
## Part 4 — Deploy to Vercel

### What Vercel is deploying

This is a **single project serving two things** from one domain:

- **Static SPA** — `vite build` → `dist/`, served from Vercel's CDN.
- **One serverless function** — `api/[[...route]].ts`, a catch-all that hands every
  `/api/*` request to the Hono app in `server/app.ts`.

`vercel.json` keeps them apart:

```json
{ "rewrites": [{ "source": "/((?!api/).*)", "destination": "/index.html" }] }
```

Every path *except* `/api/*` falls through to `index.html` so React Router can handle
deep links like `/car/toyota-innova-crysta`. The negative lookahead is what stops
`/api/cars` being answered with HTML.

### Option A — Dashboard import (recommended for the first deploy)

1. Go to <https://vercel.com/new> and sign in with GitHub.
2. **Import** `sv-venkateshwara-cars`. Authorise Vercel on the repo if prompted.
3. Vercel auto-detects **Vite**. Confirm and leave as-is:

   | Setting | Value |
   |---|---|
   | Framework Preset | Vite |
   | Build Command | `npm run build` |
   | Output Directory | `dist` |
   | Install Command | `npm ci` |
   | Root Directory | *(blank)* |
   | Node.js Version | 22.x |

4. **Expand "Environment Variables" and add all six now** — see the table in
   [Part 5](#part-5). Do this *before* the first build, not after:
   `VITE_CLOUDINARY_CLOUD_NAME` is **baked into the JS bundle at build time**, so a
   build that runs without it produces a bundle where every car image is broken.
5. **Deploy.** First build takes 2–4 minutes.

### Option B — Vercel CLI

```powershell
npm i -g vercel
vercel --version

vercel login                 # browser flow
cd "$env:USERPROFILE\projects\sv-cars"

vercel link                  # creates .vercel/ (gitignored) — link to the project
```

Set the environment variables (interactive prompts — see the
[history warning](#54-do-not-pipe-secrets-into-the-cli)):

```powershell
vercel env add DATABASE_URL production
vercel env add JWT_SECRET production
vercel env add CLOUDINARY_CLOUD_NAME production
vercel env add CLOUDINARY_API_KEY production
vercel env add CLOUDINARY_API_SECRET production
vercel env add VITE_CLOUDINARY_CLOUD_NAME production
```

Repeat with `preview` in place of `production` if you want preview deployments to work
(they will otherwise build without a database).

Deploy:

```powershell
vercel                # preview deployment, throwaway URL
vercel --prod         # production deployment
```

Confirm what landed:

```powershell
vercel ls
vercel env ls
vercel inspect --logs        # build + function logs for the latest deployment
```

## Part 5 — Where do the `.env` secrets go?

**Your actual question, answered directly.**

### 5.1 Three places, and only three

| Where | What | Committed? |
|---|---|---|
| **`.env.local`** (or `.env`) on each dev laptop | Real values, for `npm run dev:all` and the seed scripts | ❌ never — gitignored |
| **Vercel → Project Settings → Environment Variables** | Real values, for the build and the serverless function | ❌ never in git; encrypted at rest by Vercel |
| **`.env.example`** in the repo | **Placeholders only**, as documentation of which vars exist | ✅ yes — the only env file in git |

Your `.gitignore` already enforces this correctly:

```
.env.local
.env*.local
.env*
!.env.example
```

`.env*` catches everything; `!.env.example` re-admits the template. Verified working —
`git check-ignore -v .env` matches, and `.env` has never been committed.

### 5.2 The six variables

| Variable | Needed at | Read by | Where to get it |
|---|---|---|---|
| `DATABASE_URL` | runtime + local scripts | `db/index.ts`, `drizzle.config.ts`, all `scripts/seed-*`, `server/routes/public.ts` | Neon → project → Connect → **Pooled connection**. Keep `?sslmode=require` |
| `JWT_SECRET` | runtime | `server/lib/auth.ts` | Generate it (below). Not recoverable from any dashboard |
| `CLOUDINARY_CLOUD_NAME` | runtime + local | `server/lib/cloudinary.ts`, `scripts/migrate-images.ts` | Cloudinary → Programmable Media → API Keys |
| `CLOUDINARY_API_KEY` | runtime + local | same | same page |
| `CLOUDINARY_API_SECRET` | runtime + local | same | same page → **View API Keys**. 🔴 The one that really matters |
| `VITE_CLOUDINARY_CLOUD_NAME` | **build time** | `src/lib/cloudinary.ts` | Same value as `CLOUDINARY_CLOUD_NAME` |

On Vercel, tick **Production** and **Preview** for all six. Add **Development** too if
you plan to use `vercel env pull`.

> ### The one genuine trap: `VITE_` variables are compiled in, not read at runtime
>
> Vite replaces `import.meta.env.VITE_*` with a **literal string at build time**.
> Verified: the cloud name appears inlined once inside `dist/assets/index-*.js`.
>
> Consequences:
> - It must be present **when the build runs**. Adding it afterwards changes nothing
>   until you **redeploy**.
> - Editing it in the Vercel dashboard does **not** take effect on the live site until
>   the next build.
> - It is **public** — visible in the bundle and in every image URL. That is fine and
>   by design; a Cloudinary cloud name grants no access on its own.
>
> The other five are read from `process.env` inside the function at request time, so
> changing those *does* take effect on the next deployment without a rebuild.
>
> **Never give a `VITE_` prefix to `CLOUDINARY_API_SECRET`, `JWT_SECRET` or
> `DATABASE_URL`.** That single character would publish them to every visitor.

### 5.3 Creating `.env.local` on the other laptop

Do **not** copy `.env` across in the zip. Four of the five secrets are recoverable
from their own dashboards in under a minute, and the fifth can simply be regenerated.

```powershell
cd "$env:USERPROFILE\projects\sv-cars"
Copy-Item .env.example .env.local
notepad .env.local
```

Fill in:

- `DATABASE_URL` — from the Neon dashboard.
- `CLOUDINARY_*` — from the Cloudinary dashboard.
- `JWT_SECRET` — generate a fresh one:

  ```powershell
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```

  A **new** `JWT_SECRET` is fine. Its only effect is that existing admin sessions are
  invalidated — the owner logs in again. The password itself is a bcrypt hash in the
  database and is unaffected.

**Neatest alternative — let Vercel be the source of truth.** Once the six vars are set
in the Vercel project, pull them down instead of retyping:

```powershell
vercel env pull .env.local
```

This writes a real `.env.local` from the Vercel project (gitignored, so it stays local).
Now there is exactly one place the values are maintained, and every laptop syncs from
it. This is what I would do.

### 5.4 Do not pipe secrets into the CLI

```powershell
# ❌ this writes your database password into
#    %APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
echo "postgresql://user:realpassword@..." | vercel env add DATABASE_URL production
```

PowerShell records command lines to a plaintext history file that persists across
reboots. Use the **interactive prompt** (`vercel env add NAME production` with no pipe)
or the **dashboard**, which is why the dashboard is recommended above.

Also never put a real secret in: a screenshot, a chat message, a commit message, a
GitHub issue, or `.env.example`.

### 5.5 Two dead entries in your current `.env`

Your `.env` has eight keys. Two are read by nothing in this codebase — verified by
grepping `server/`, `scripts/`, `db/`, `src/`, `api/`, `drizzle.config.ts` and
`vite.config.ts`:

| Key | Status |
|---|---|
| `DATABASE_URL_POOLED` | ❌ unused — `DATABASE_URL` should already be the pooled string |
| `CLOUDINARY_URL` | ❌ unused — an alternative SDK config format; `server/lib/cloudinary.ts` configures from the three separate vars |

Harmless, but **do not add these two to Vercel.** `CLOUDINARY_URL` embeds the API
secret in a URL, so carrying it around is extra exposure for zero benefit. Deleting
both from `.env` is safe.

### 5.6 Rotating a leaked secret

| Secret | How |
|---|---|
| `DATABASE_URL` | Neon → Roles → reset password → update Vercel + `.env.local` |
| `CLOUDINARY_API_SECRET` | Cloudinary → API Keys → rotate → update both |
| `JWT_SECRET` | Generate a new one → update both. Admin sessions drop; nothing else |
| Admin password | `npm run create:admin -- <email> '<new-password>'` (upsert by email) |

After any change on Vercel, **redeploy** — see [Part 8](#part-8).

## Part 6 — Seed the production database

The migration and seed scripts are **local** (`tsx`), not part of the deployment. They
talk to Neon directly, so run them from either laptop with the production
`DATABASE_URL` in `.env.local`.

**Skip this entirely if you are pointing at the same Neon database you already
seeded** — it is already populated. This is for a fresh database.

```powershell
npm run db:push          # push the Drizzle schema to Neon
npm run seed:settings    # the single settings row (phone, pickup, default rates)
npm run seed:locations   # the branch/city rows
npm run create:admin -- owner@example.com 'a-real-strong-password'
npm run migrate:images   # 8 cars, ~43 images -> Cloudinary
npm run migrate:images   # run AGAIN: must report 0 uploads, 0 inserts
```

**Order matters.** `seed:locations` must run before `migrate:images` — cars carry a
`locationId` foreign key into `locations`, and a null there hides the car from every
city-filtered view.

The second `migrate:images` run is the idempotency proof. If it re-uploads or
duplicates rows, stop and fix the script before you ever run it against a database
holding the owner's real prices — a non-idempotent migration would reset them to 0.

Inspect the result:

```powershell
npm run db:studio        # opens Drizzle Studio in the browser
```

<a name="part-7"></a>
## Part 7 — Verify the deployment

Replace `<url>` with your deployment URL.

### 7.1 The API is alive and not shadowed by the SPA rewrite

```powershell
curl.exe -s "https://<url>/api/health"
```

Expect `{"ok":true,"db":true}`.

- `db: false` → `DATABASE_URL` is wrong or missing on Vercel.
- **HTML instead of JSON** → the `vercel.json` rewrite is swallowing `/api`. The
  negative lookahead `/((?!api/).*)` is what prevents this.
- 404 → the function did not build. Check `vercel inspect --logs`.

```powershell
curl.exe -s "https://<url>/api/cars" | Select-Object -First 1
curl.exe -s -o NUL -w "%{http_code}`n" "https://<url>/api/settings"
```

### 7.2 Admin routes reject anonymous callers

```powershell
foreach ($p in @("cars","settings","me","uploads/sign")) {
  $code = curl.exe -s -o NUL -w "%{http_code}" "https://<url>/api/admin/$p"
  Write-Host "$p -> $code"
}
```

**Every one must be `401`.** A `200`, `404` or `500` means that route is reachable
without authentication.

### 7.3 SPA deep links work

Open each directly in the browser (not by clicking through from the home page — that
would not exercise the rewrite):

- `https://<url>/`
- `https://<url>/all-cars`
- `https://<url>/car/toyota-innova-crysta` ← must render, not 404
- `https://<url>/booking?carId=toyota-innova-crysta&days=3&mode=driver`
- `https://<url>/admin/login`
- `https://<url>/nonsense-route` ← must show the in-app 404, inside the customer layout

### 7.4 Images actually load

Open `/all-cars` with devtools → Network → Img. Every request should go to
`res.cloudinary.com/...` and return **200**.

If they all 404 or the console shows
`[cloudinary] VITE_CLOUDINARY_CLOUD_NAME is not set`, that variable was missing **at
build time**. Add it and **redeploy** — setting it alone will not fix the already-built
bundle. See [5.2](#52-the-six-variables).

### 7.5 No secret reached the browser

```powershell
npm run build
Select-String -Path dist\assets\*.js -Pattern "api_secret|JWT_SECRET|postgresql://|neon\.tech"
```

**Must return nothing.** Verified clean on this machine. The only Cloudinary value
permitted in the bundle is the cloud name.

### 7.6 Owner flows

Log in at `/admin`, then confirm: the fleet lists real cars · editing a price persists
across a refresh · a photo upload completes and appears on the public detail page ·
availability toggles hold · the WhatsApp CTA opens a message containing the real phone
number, car, dates and total.

The `sv_session` cookie sets `secure` in production; Vercel is HTTPS, so this works.
It will *not* work over plain `http://`.

<a name="part-8"></a>
## Part 8 — Day-to-day: redeploy and rollback

### Deploy a code change

Git-connected projects deploy on push. No CLI needed:

```powershell
git add -A
git commit -m "fix: whatever changed"
git push
```

Vercel builds `master`/`main` → production, and every other branch or PR → a preview URL.

### Redeploy without a code change

Needed after editing an environment variable — especially `VITE_CLOUDINARY_CLOUD_NAME`,
which is compiled into the bundle.

```powershell
vercel --prod --force        # rebuild, ignoring the build cache
```

Or dashboard: **Deployments → ⋯ on the latest → Redeploy**. Leave *"Use existing build
cache"* **unchecked** when an env var changed, otherwise the stale bundle is reused.

### Roll back

Dashboard: **Deployments** → pick a known-good one → **⋯ → Promote to Production**.
Instant, no rebuild — Vercel keeps every previous build.

### Useful commands

```powershell
vercel ls                    # recent deployments
vercel inspect --logs        # build + runtime logs, latest deployment
vercel logs <deployment-url> # function logs for a specific deployment
vercel env ls                # which vars are set, per environment
vercel env rm NAME production
```

|---|---|---|
| `git log` → "not a git repository" after extracting | Zipped with `Compress-Archive` — it dropped `.git` | Re-zip with `tar.exe` ([1.2](#12--zip-the-staged-copy--use-tarexe-not-compress-archive)) |
| `robocopy` "failed" with exit code 1 | 1 means *files were copied* | Not an error. Only ≥ 8 is |
| `npm ci` fails on `sharp` | Native build, or a stale lockfile | `npm cache clean --force`, confirm Node ≥ 22, retry |
| `npm ci` intermittent `EBUSY` | Project sits under OneDrive | Move it outside the OneDrive folder |
| `npm run lint` fails, `tests/ui/fixtures.ts` | Known — missing `heroImage` | [0.2](#02--known-type-error--read-before-you-panic-on-the-other-laptop). Does not block deploy |
| Build succeeds, every image broken | `VITE_CLOUDINARY_CLOUD_NAME` absent at build time | Add it, then `vercel --prod --force` |
| `/api/*` returns HTML | `vercel.json` rewrite is catching `/api` | Restore `"source": "/((?!api/).*)"` |
| `/api/health` → `db:false` | Bad or missing `DATABASE_URL` on Vercel | Re-add it; use the **pooled** Neon string with `?sslmode=require` |
| Deep link `/car/...` → 404 | Missing SPA rewrite | Confirm `vercel.json` is committed |
| Admin login 401 with the right password | No admin row, or `JWT_SECRET` differs from the one used at login | `npm run create:admin -- <email> '<pw>'` |
| Logged out on every page load | Cookie needs `secure`; you are on `http://` | Use the `https://` URL |
| Owner's edit not visible to customers | Deliberate: public GETs cache `s-maxage=60` | Wait ≤ 60s. Admin views are `no-store` and instant |
| First request after idle is slow | Neon scales to zero; ~300–800 ms wake | Expected. The edge cache hides it from most visitors |
| Function bundle too large | `sharp` pulled into the function | Keep `sharp` a devDependency, used only in `scripts/` |
